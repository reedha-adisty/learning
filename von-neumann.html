01 — Latar Belakang

Apa itu Arsitektur Von Neumann?

Arsitektur Von Neumann adalah model desain komputer yang diusulkan oleh matematikawan John von Neumann pada tahun 1945 dalam dokumen terkenalnya "First Draft of a Report on the EDVAC". Model ini menjadi fondasi bagi hampir semua komputer digital modern yang kita gunakan hingga saat ini.

Inovasi revolusioner dari model ini adalah konsep Stored-Program Computer (Komputer dengan Program Tersimpan) — di mana data dan instruksi program disimpan bersama dalam satu memori yang sama, sehingga program dapat dimodifikasi layaknya data biasa.

Konsep Kunci

Stored-Program Concept

Sebelum Von Neumann, komputer seperti ENIAC diprogram dengan cara fisik (memasang kabel). Von Neumann mengusulkan bahwa instruksi program disimpan dalam memori, sama seperti data — revolusi yang memungkinkan komputer menjadi mesin general-purpose.

  • P-01

    Unified Memory: Data dan instruksi disimpan dalam memori yang sama menggunakan format biner yang sama. Komputer tidak membedakan keduanya secara fisik.

  • P-02

    Sequential Execution: Instruksi dieksekusi secara berurutan satu per satu, kecuali ada instruksi percabangan (jump/branch) yang mengubah alur eksekusi.

  • P-03

    Binary Representation: Semua data dan instruksi direpresentasikan dalam format biner (0 dan 1) di dalam memori komputer.

  • P-04

    Fixed Architecture: CPU memiliki set instruksi tetap (Instruction Set Architecture/ISA), sementara program yang berbeda menggunakan instruksi-instruksi tersebut secara berbeda.

  • P-05

    Von Neumann Bottleneck: Keterbatasan bandwidth antara CPU dan memori karena keduanya berbagi bus yang sama untuk transfer data dan instruksi.

🧠

Control Unit (CU)

Otak komputer yang mengoordinasikan seluruh operasi. CU membaca instruksi dari memori, mendekode instruksi tersebut, lalu mengirimkan sinyal kontrol ke komponen lain untuk mengeksekusinya. CU tidak melakukan kalkulasi sendiri, tetapi mengatur siapa yang melakukan apa dan kapan.

Fungsi: Fetch → Decode → Manage Execution → Control Data Flow
⚙️

ALU — Arithmetic Logic Unit

Komponen yang melakukan semua operasi matematika dan logika. ALU menerima input dari register, melakukan operasi, dan mengembalikan hasilnya ke register (biasanya Accumulator). Setiap kalkulasi yang pernah dilakukan komputer, terjadi di sini.

ADD SUB MUL DIV AND OR NOT CMP
💾

Register

Penyimpanan tercepat dalam komputer, berada di dalam CPU. Register menyimpan data yang sedang aktif diproses. Kapasitasnya sangat kecil tetapi kecepatannya luar biasa (akses dalam nanosecond).

PC — Program Counter

Menyimpan alamat instruksi berikutnya yang akan dieksekusi

IR — Instruction Register

Menyimpan instruksi yang sedang dieksekusi saat ini

MAR — Memory Address Reg

Menyimpan alamat memori yang akan diakses

MDR — Memory Data Reg

Menyimpan data yang baru dibaca/akan ditulis ke memori

ACC — Accumulator

Menyimpan hasil operasi ALU dan salah satu operand

🗄️

Memori Utama (Main Memory / RAM)

Tempat penyimpanan program yang sedang berjalan dan datanya. Diorganisir sebagai array dari lokasi bernomor (alamat). Setiap alamat memori dapat menyimpan data biner. Memori bersifat volatile — isinya hilang saat komputer dimatikan. Dalam arsitektur Von Neumann, instruksi dan data berada dalam ruang memori yang sama.

Alamat 0000: [instruksi LOAD 0010]
Alamat 0001: [instruksi ADD 0011]
Alamat 0002: [data: 25 ]
Alamat 0003: [data: 10 ]
🖥️

I/O Devices (Perangkat Input/Output)

Antarmuka antara komputer dengan dunia luar. Perangkat input memasukkan data ke komputer, perangkat output mengeluarkan hasil pemrosesan. I/O dikelola oleh CPU melalui instruksi I/O atau mekanisme interrupt.

INPUT DEVICES

Keyboard, Mouse, Scanner, Mikrofon, Kamera, Sensor

OUTPUT DEVICES

Monitor, Printer, Speaker, LED, Network Card

03 — Machine Cycle

Siklus Eksekusi Instruksi

Siklus mesin (machine cycle / instruction cycle) adalah serangkaian langkah yang dilakukan CPU untuk mengeksekusi satu instruksi. Siklus ini diulang terus-menerus selama komputer berjalan. Dikenal juga sebagai siklus Fetch-Decode-Execute (FDE).

01

FETCH — Pengambilan Instruksi

CPU mengambil instruksi berikutnya dari memori utama. Alamat instruksi tersimpan dalam Program Counter (PC). Setelah fetch, PC otomatis bertambah untuk menunjuk ke instruksi berikutnya.

1. MAR ← PC             // Kirim alamat ke MAR
2. MDR ← Memori[MAR]   // Baca isi memori ke MDR
3. IR ← MDR              // Salin instruksi ke IR
4. PC ← PC + 1           // Increment program counter
02

DECODE — Penerjemahan Instruksi

Control Unit menganalisis instruksi yang ada di Instruction Register (IR). CU memecah instruksi menjadi opcode (kode operasi) dan operand (data/alamat), lalu menghasilkan sinyal kontrol yang diperlukan.

IR berisi: [OPCODE | OPERAND]
Contoh:    [ADD   | ADDR_0010]
↓
CU → Sinyal ke ALU: "siapkan operasi ADD"
CU → Sinyal ke Memori: "baca alamat 0010"
03

EXECUTE — Eksekusi Instruksi

Instruksi benar-benar dijalankan. Untuk instruksi aritmetika/logika, ALU melakukan kalkulasi. Untuk instruksi memori, data dibaca/ditulis. Untuk instruksi I/O, data dikirim ke/dari perangkat. Untuk jump, PC diperbarui ke alamat baru.

Tipe Eksekusi:
• Aritmetika : ALU melakukan ADD/SUB/MUL/DIV
• Logika     : ALU melakukan AND/OR/NOT/XOR
• Memori     : CPU membaca/menulis ke RAM
• Jump       : PC ← alamat tujuan
• I/O        : Transfer data ke/dari perangkat
04

STORE — Penyimpanan Hasil

Hasil dari eksekusi disimpan kembali. Bisa ke register (Accumulator), memori utama, atau dikirim ke perangkat output. Setelah ini, siklus kembali ke fase Fetch untuk instruksi berikutnya — terus berulang hingga ada instruksi HALT.

Hasil → Accumulator (register internal)
atau
Hasil → Memori[alamat] (via STORE instruction)
atau
Hasil → Output Device (via OUT instruction)
↓
→ Kembali ke FETCH (siklus berikutnya)
Catatan Penting

Satu Instruksi = Beberapa Clock Cycle

Meskipun kita menyederhanakannya menjadi 4 fase, dalam CPU modern satu instruksi bisa membutuhkan beberapa clock cycle. Teknik seperti pipelining memungkinkan CPU mengeksekusi beberapa instruksi secara tumpang tindih (overlapping) untuk meningkatkan throughput.
